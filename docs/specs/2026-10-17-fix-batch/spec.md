# ReviewPilot 质量修复 Spec（2026-10-17）

## 背景

最近 5 个提交（`e04d927` → `0eb1810`）完成了职责拆分、GitHub/模型调用健壮性补强、前端组件化重构和中文注释补充。工作区另有一整套未提交的鉴权/脱敏功能（Bearer 准入、生产配置校验、错误脱敏、DTO 不可变快照、前端访问令牌入口），当前后端 202 个测试通过。

审查发现的问题分布在三处：

1. **已提交历史**：41 个类的 Javadoc 位于注解之后而失效；请求预算耗尽后仍会发起一次模型调用；分页截断在整页边界误报；GitHub 抓取的异常捕获过宽；PR URL 未拒绝 `.`/`..` 段。
2. **未提交工作区**：鉴权/准入过滤器作用于所有路径且所有 POST 都消耗审查额度；错误脱敏后日志可观测性不足；个人工具配置与笔记混在未跟踪文件中。
3. **前端与仓库卫生**：风险列表展开状态用过滤后下标绑定；评审计时器未在卸载时清理；调试截图和 Playwright 快照已被提交；提交粒度过粗。

本次修复不新增产品功能，目标是消除上述缺陷，使工作区达到可提交、可验证、可回滚的状态。

## 目标

- 修正已确认的 P0/P1/P2 缺陷，不新增产品功能。
- 使工作区达到可提交状态：测试全绿、无调试产物、无失效文档、提交历史按主题清晰拆分。
- 为每项修复留下可观测的验证证据（命令输出或行为观察），而不是"应该没问题"。

## 功能需求

### 提交前必修（P0）

- **F1 删除调试残留**：审查流水线中不应保留任何以文件名列表形式存在的临时注释；代码行为不变。
- **F2 清理失效文档**：删除 41 个类中位于注解之后、重复且不被文档工具识别的注释；每个类保留原有的完整职责说明，生成的 API 文档中不再出现重复条目。
- **F3 预算耗尽硬停止**：请求的墙钟预算耗尽后，不得再发起任何模型调用。系统先尝试把最后一次模型回复解析为审查 JSON（该解析不得触发修复性补调）；解析成功则采用，失败则返回降级审查结果——保留确定性规则检测出的风险，summary 明确说明"时间预算耗尽"。正常达到最大轮次时的强制收尾不受影响。
- **F4 准入作用域收敛**：鉴权与准入只作用于 API 路径；只有审查提交（POST `/api/review`）消耗审查频率/并发额度，其他端点不会因新增而被误计费。鉴权开启时，文件查询仍需有效令牌。
- **F5 个人文件策略**：仓库保留 `AGENTS.md` 与 `.claude/agents/`；忽略本地工具配置（`.claude/settings.local.json`、`.codex/`、`.mewcode/`）、根目录问题笔记、面试文档和截图。

### 安全与可靠性（P1）

- **F6 GitHub 异常分类**：网络超时、响应过大等上游传输故障继续映射为 502；编程错误（空指针、非法状态等）不得伪装成上游故障，保留 500 并记录 ERROR。
- **F7 PR URL 段校验**：owner 或 repo 为 `.` 或 `..` 时，请求在进入任何 GitHub 调用前以 400 拒绝；正常 URL 行为不变。
- **F8 可观测性恢复**：每个 API 请求都有可关联的 request ID，写入服务端日志上下文并保留在响应头；5xx 日志包含异常类型与堆栈，但不得包含上游响应体、令牌或模型密钥。
- **F9 分页截断准确**：文件数恰好为整页倍数且落在页数上限的完整 PR，不再被标记为截断；真正超过上限的 PR 仍标记截断。
- **F10 前端展开状态稳定**：风险列表的展开状态与具体风险绑定；切换 HIGH/MEDIUM/LOW 过滤后，不会展开到另一条风险。
- **F11 前端计时器清理**：评审进行中组件卸载时，计时器停止，不再持续更新。
- **F12 文件查询准入边界**：GET 文件查询保持应用层不限流，但鉴权与仓库白名单仍然生效；部署文档明确由网关承担请求速率限制（应用层不新增 GET 限流）。

### 仓库卫生与交付（P2）

- **F13 调试产物清理**：从当前版本移除根目录 4 张 PNG 和 `.playwright-mcp/page-*.yml`，`docs/security-access-mobile.png` 不入库；`.gitignore` 覆盖这些路径。已存在于历史提交中的文件不通过改写历史删除。
- **F14 提交可审查**：现有鉴权功能先形成基线提交；本次修复按主题拆分为多个提交（文档清理、预算语义、准入与安全、前端、仓库卫生），每个提交可独立编译和回滚。

## 非功能需求

- **N1 技术栈与兼容**：保持 Java 17 / Spring Boot 3 / Vue 3；不新增运行时依赖；除既定的降级 summary 外，不改变现有成功/错误响应结构（request ID 仍通过响应头传递）。
- **N2 测试覆盖**：后端 `mvn -o test` 全绿，测试数不少于当前 202；F3、F4、F6、F7、F8、F9 必须有回归测试；前端 `node --test src/api/review.test.js` 与 `npm run build` 通过。
- **N3 性能**：预算耗尽路径不再产生额外模型往返；过滤器与 request ID 逻辑为常数开销；不新增同步网络调用。
- **N4 安全**：日志和响应中不得出现上游响应体、访问令牌、GitHub Token 或模型密钥；令牌比较仍为常量时间；request ID 由服务端生成，不信任客户端输入。
- **N5 可维护性**：修复不引入新的抽象层；Javadoc 位于注解之前且每个类只有一份职责说明；个人文件与产品代码隔离。
- **N6 可观测性**：request ID 同时出现在响应头和该请求的服务端日志中；预算降级在 summary 与日志中可识别。
- **N7 提交质量**：基线提交先于修复提交；每个提交可独立编译；提交信息说明"为什么"而不只是"改了什么"。
- **N8 文档同步**：`docs/security-deployment.md` 补充 GET 文件查询的应用层限流边界；四份 spec 文档保存在 `docs/specs/2026-10-17-fix-batch/`。

## 不做的事

- 不新增产品功能：不做多用户权限、异步审查任务、请求硬取消、每日费用配额或应用层 GET 限流。
- 不引入新依赖、缓存中间件、消息队列或新的基础设施。
- 不改写已有 Git 历史：已进入历史提交的截图/Playwright 文件只从当前版本移除，不通过 rebase 抹除；不调整既有提交信息。
- 不做任何分支 fetch/merge/rebase（按用户说明，分支已合并）。
- 不改变现有成功响应与错误响应 JSON 结构；request ID 只走响应头。
- 不处理问题笔记、面试文档的内容质量，也不把它们当作产品文档维护。
- 不处理 `26d9f3d`（多模型切换）引入的功能问题。
- 不做超出清单的全面重构、重命名或注释重写（YAGNI）。

## 验收标准

### 行为验收

- **AC1（F1）**：代码中不再存在以文件名列表形式出现的临时注释；后端编译与全部测试通过。
- **AC2（F2）**：对受影响类运行文档工具，41 个类各自只输出一份原有职责说明；不存在"注解之后紧跟文档注释"的模式（可用脚本扫描验证）。
- **AC3（F3）**：传入已过期预算时，模型调用次数不因"强制收尾"而增加；最后一次回复为合法 JSON 时被采用；否则最终结果保留规则风险且 summary 含"预算耗尽"；最大轮次正常收尾的既有测试仍通过。
- **AC4（F4）**：鉴权/准入只处理 API 路径；非审查 POST 不消耗审查额度；`/api/review` 超限仍返回 429；健康检查与预检仍放行。
- **AC5（F5）**：`AGENTS.md` 和 `.claude/agents/` 被跟踪；`.claude/settings.local.json`、`.codex/`、`.mewcode/`、根目录笔记、面试文档在 `git status` 中不再出现（被忽略）。
- **AC6（F6）**：网络超时仍返回 502；模拟空指针/非法状态时返回 500 且日志为 ERROR，不再被描述为上游故障。
- **AC7（F7）**：owner/repo 为 `.` 或 `..` 的 URL 返回 400，且没有 GitHub 出站请求；正常 URL 行为不变。
- **AC8（F8）**：每个 API 响应带 `X-Request-ID`；同一次请求的日志包含同一 ID；5xx 日志不出现上游响应体、令牌或密钥；响应 JSON 结构不变。
- **AC9（F9）**：文件数恰好为整页倍数且已抓完的 PR 返回 `truncated=false`；真正超过页数上限的 PR 返回 `truncated=true`。
- **AC10（F10）**：切换风险级别过滤后，展开状态仍对应原风险，不会展开到别的条目。
- **AC11（F11）**：评审进行中卸载组件后，计时器停止更新。
- **AC12（F12）**：部署文档明确"GET 文件查询应用层不限流、由网关限流"；鉴权开启时 GET 无令牌返回 401，有令牌正常；代码未新增 GET 限流。

- **AC14（F14）**：提交序列为"基线提交 + 按主题拆分提交"；每个提交可独立编译；提交信息说明动机。
