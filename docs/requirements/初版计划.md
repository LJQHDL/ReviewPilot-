# 五、核心模块设计（重点）

# 1. GitHub PR 获取模块

## 功能

输入：

```text
https://github.com/owner/repo/pull/12
```

解析：

```text
owner
repo
pull_number
```

调用 GitHub API：

```text
GET /repos/{owner}/{repo}/pulls/{pull_number}/files
```

获取：

- changed files
- patch diff

------

# 2. Diff Parser（核心）

## 作用

把 patch diff 解析成：

```text

新增代码
删除代码
```

# 4. Risk Detector（核心亮点）

# 这是你项目最加分的模块

先不用 AI。

先规则检测。

------

## 例如：

### 检测：

```text

```

------

## 风险等级：

```text

MEDIUM
LOW
```

------

## 示例

```text

但未发现：
finally unlock()

```

# 十、比赛时怎么讲（非常关键）

评委问：

> “你和直接 GPT Review 有什么区别？”

你回答：

# “我们做了分阶段分析架构”

例如：

```text
1. 先做规则风险检测
2. 再做上下文增强
3. 最后才做AI分析
```

这样：

- 降低误报
- 节省 token
- 提高准确率

这一套说出来就很专业。
